### 🏗️ What is this Project About?

This project is called **Refactoring with AWS** (re-architecting the `vprofile` web application stack).

* **Before (Lift & Shift / IaaS):** We took the application and manually installed every single service (Tomcat, MySQL, RabbitMQ, Memcached) onto regular virtual machines or EC2 instances.
* **Now (Refactoring / PaaS & SaaS):** Instead of babysitting servers ourselves, we rebuild the architecture using **AWS Managed Services** (Platform as a Service & Software as a Service). AWS handles the heavy lifting—like server maintenance, scaling, and backups—so we can focus on the application itself.

---

### 📝 The Breakdown

**1. Why Refactor? (The Problem with Traditional Setups)**
Running databases, web servers, DNS, and DHCP on physical servers, local VMs, or regular EC2 instances creates massive **operational overhead**:

* **Too Many Teams Needed:** You need separate Cloud, Virtualization, Data Center Ops, Monitoring, and SysAdmin teams just to keep things running.
* **High Costs:** Local data centers demand heavy upfront **CapEx** (buying hardware) and ongoing **OpEx** (maintaining it).
* **Hard to Scale & Automate:** Processes stay manual, time-consuming, and teams constantly struggle with uptime and scaling spikes.

**2. The Objectives & Benefits of Refactoring**
Switching from **IaaS** to **PaaS & SaaS** gives you:

* **Boosted Agility & Business Continuity:** Roll out new features faster with better reliability and performance.
* **Low Operational Overhead:** AWS manages the underlying infrastructure and scaling, so you don't need massive teams.
* **Elastic & Flexible:** Scales up and down automatically based on traffic.
* **Pay-As-You-Go:** Only pay for what you actually use.
* **Infrastructure as Code (IaC):** Cloud-native services make deep automation easy.

**3. Old Stack vs. New AWS Managed Services** 🔄

| Old Component (Lift & Shift) | New AWS Service (Refactored) | What It Does |
| --- | --- | --- |
| **Tomcat on EC2 / VM** | **AWS Elastic Beanstalk** 🌱 | Automatically creates & manages EC2 instances, an Application Load Balancer (ALB), Auto Scaling, and an S3 bucket for artifacts (or uses your own). |
| **NFS (Network File System)** | **Amazon EFS or S3** 🪣 | Managed cloud storage (S3 also stores app artifacts for one-click deployments). |
| **MySQL on EC2 / VM** | **Amazon RDS** 🗄️ | Managed database platform with quick setup, easy scaling, and automatic regular backups. |
| **Memcached on EC2 / VM** | **Amazon ElastiCache** ⚡ | Managed caching service. |
| **RabbitMQ on EC2 / VM** | **Amazon MQ (ActiveMQ)** 📨 | Managed message broker. |
| **DNS Server** | **Amazon Route 53** 🌐 | Managed DNS routing. |
| **Direct Origin Serving** | **Amazon CloudFront** 🚀 | Content Delivery Network (CDN) that caches content for fast global delivery with SSL/HTTPS. |

**4. How the Architecture Works (Traffic Flow)** 🗺️

1. **User ➡️ Route 53:** A user enters the website URL, and Route 53 resolves it to the CloudFront endpoint.
2. **CloudFront (CDN):** Caches static/common content to serve a global audience fast, then forwards requests to the backend.
3. **Application Load Balancer (ALB):** Part of Elastic Beanstalk; receives traffic from CloudFront and distributes it.
4. **EC2 Auto Scaling Group (Tomcat):** Managed by Beanstalk; runs the web app. **Amazon CloudWatch Alarms** watch the group and trigger scale-out or scale-in automatically.
5. **S3 Bucket:** Stores application artifacts so you can deploy updates with a single button click.
6. **Backend Services:** The Beanstalk app talks behind the scenes to **Amazon RDS** (database), **ElastiCache** (cache), and **Amazon MQ** (messaging).

**5. Step-by-Step Execution Plan** 📋
Here is the exact order we will build this in the AWS Console:

1. **Log in to AWS** and create an **EC2 Key Pair** (so you can SSH into Beanstalk's EC2 instances if ever needed).
2. **Create a Backend Security Group:** A single security group to hold RDS, ElastiCache, and ActiveMQ.
3. **Launch Backend Services:** Create **Amazon RDS**, **ElastiCache**, and **Amazon MQ (ActiveMQ)**.
4. **Create Elastic Beanstalk Environment:** This automatically spins up its own EC2 instances, Load Balancer, and dedicated Security Groups.
5. **Update Backend Security Group Rules:**
* Allow incoming traffic from the **Beanstalk Instance Security Group**.
* Allow **internal traffic** inside the Backend Security Group so the backend services can communicate with each other.


6. **Initialize the RDS Database:** Launch a temporary EC2 instance, connect to RDS using a MySQL login from that EC2, and initialize the database.
7. **Configure Beanstalk & ELB:**
* Change the Beanstalk **health check path to `/login**` (since the `vprofile` app serves its landing page there).
* Add a **Port 443 (HTTPS) listener** to Beanstalk's Elastic Load Balancer.


8. **Build the Artifact:** Collect the endpoints for RDS, ElastiCache, and Amazon MQ, plug them into the source code's `application.properties` file, and build the artifact.
9. **Deploy to Beanstalk:** Upload and deploy the built artifact to your Beanstalk environment.
10. **Set up CloudFront:** Create a CloudFront CDN distribution with an **SSL certificate** for HTTPS.
11. **Update DNS:** Point your domain to the CloudFront/Load Balancer endpoint using **GoDaddy** or **Amazon Route 53** public DNS zones.
12. **Test:** Open the URL in your browser and verify the live refactored app!

---

### 🚀 Summary

* **Refactoring** replaces manually managed servers (IaaS) with AWS managed services (**PaaS & SaaS**) to slash operational overhead, improve scaling, and cut wasted costs.
* **Frontend:** Completely managed by **Elastic Beanstalk** (EC2 + ALB + Auto Scaling + CloudWatch Alarms + S3), fronted by **CloudFront** (CDN) and **Route 53** (DNS).
* **Backend:** Powered by **RDS** (MySQL), **ElastiCache** (Memcached), and **Amazon MQ** (ActiveMQ), all secured together inside one Backend Security Group.
* **Workflow:** Build the backend ➡️ spin up Beanstalk ➡️ link Security Groups ➡️ initialize RDS via a helper EC2 ➡️ bake backend endpoints into `application.properties` ➡️ deploy ➡️ attach CloudFront + HTTPS + DNS ➡️ test!
